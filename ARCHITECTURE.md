# FCF — Фрактальное Когнитивное Поле

*Нейро-символическая модель языка на саморганизующейся гиперсфере.*  
*Никаких трансформеров. Никакого обратного распространения. Никакого градиентного спуска.*

---

## 1. Представление знаний: от токена к вектору

Каждый токен SentencePiece BPE (146K или 256K словаря) является **концептом** — автономной единицей знания, представленной точкой на единичной гиперсфере в 768-мерном пространстве.

Базовый BPE — `bpe_ru_146k.model` (146 000 токенов). Морфемный BPE — `bpe_morph.model` (256 000 токенов), обучен на корпусе с `\u037E`-разделителями между морфемами русского слова. На тестовой выборке: 20.7% слов — 1 токен, 71.3% — ≤2 токенов, 99.7% — ≤5 токенов.

### 1.1 Двухуровневое кодирование

Концепт хранится как пара `(латентный_код, вектор)`:

```
z ∈ ℝ^{L}     — латентный код (разреженный, подпространственно-расщеплённый)
v ∈ 𝕊^{D-1}  — единичный вектор на гиперсфере (D = 768)
v = normalize(z · B)  где B ∈ ℝ^{L×D} — ортонормированный базис (общий для всех)
```

Такое разделение даёт:
- **Код** — внутреннее представление, доступное для пластичности
- **Базис** — общая система координат, единая для всего поля
- **Вектор** — внешнее представление, используемое для сравнения и поиска

### 1.2 Подпространственно-кинетическое расщепление

Латентный код разделён на три функциональных подпространства:

| Подпространство | Доля | Функция | Пластичность |
|---|---|---|---|
| `z_c` (content) | ~60% | Семантическая идентичность | Медленная (L1-регуляризована) |
| `z_a` (attention) | ~25% | Контекстуальное поведение | Быстрая |
| `z_m` (meta) | ~15% | Морфологическая / грамматическая форма | Средняя |

Градиенты проецируются в пространство кода, маскируются по подпространствам, и каждое подпространство обновляется со своей скоростью. Это предотвращает катастрофическое забывание: содержание концепта остаётся стабильным, в то время как контекстуальная активность адаптируется быстро.

## 2. Пластичность: как поле учится

Обратное распространение заменено пятью локальными механизмами пластичности, работающими непосредственно с векторами концептов.

### 2.1 STDP (Spike-Timing-Dependent Plasticity)

Если токен A предшествует токену B в тексте, латентный код B сдвигается к коду A. Величина притяжения модулируется:

- **PMI (Pointwise Mutual Information)** — пары ниже порога отсекаются
- **Вес расстояния** — ближайшие токены влияют сильнее
- **Частотный вес** — редкие токены получают пропорционально более сильные обновления
- **Qwen-фактор** — предвычисленный семантический сигнал от Qwen модулирует LR каждой пары (усиление/отталкивание/нейтрально)
- **Полевой ключ** — межсекторные пары тормозятся
- **Beam-pull** — мягкое притяжение к ближайшему лучу Transition Manifold

Все пары микробатча обрабатываются одной GPU-операцией scatter_add.

### 2.2 Негативная выборка

Случайные концепты отталкиваются от каждого обновлённого. Сила отталкивания взвешивается ошибкой предсказания концепта: чем хуже модель его знает, тем сильнее регуляризация. Полевые ключи отфильтровывают недопустимые негативы.

### 2.3 Контрастивная цель

Жёсткий майнинг среди top-K ближайших концептов. Похожие, но не встречающиеся вместе и не связанные полем — разносятся. Межполевые пары (разные секторы) отталкиваются агрессивно; внутриполевые — мягко, сохраняя кластерную структуру.

### 2.4 Латеральное торможение

Все обновлённые в батче концепты отталкиваются по геодезической сферы. Предотвращает коллапс: если все векторы станут идентичными, вся информация потеряна. Реализовано через риманов градиент.

### 2.5 Центроидное притяжение

Все токены предложения слабо притягиваются к общему центру. Функционирует как регуляризатор уровня предложения.

## 3. Динамическая размерность: саморегуляция ёмкости поля

Поле не имеет фиксированной размерности. Ёмкость автоматически растёт и сжимается в зависимости от плотности знаний.

### 3.1 L1-регуляризация на подпространство z_c

Каждый концепт индивидуально отслеживает свою плотность — долю активных компонент в `z_c`:

```
density(cid) = mean(|z_c[cid]| > 1e-4)
```

L1-регуляризация стремится удержать плотность каждого концепта около 8%:

```
strength = l1_lambda[cid] · max(0, 1.0 — CE · 2.0)
z_c = sign(z_c) · max(0, |z_c| — strength)
```

- Высокая ошибка предсказания (CE) → слабая L1 → код плотнее
- Низкая ошибка → сильная L1 → код разреженнее

Каждый концепт имеет свой `l1_lambda[cid]`, который адаптируется каждые 2 эпохи.

### 3.2 Рост ёмкости (grow_capacity)

Когда средняя плотность по всем концептам превышает 15%, поле автоматически расширяется:

1. Генерируются новые ортогональные базис-векторы (QR-разложение)
2. Базис растёт: `B ∈ ℝ^{L×D} → B ∈ ℝ^{L'×D}` (L' = L × 1.5)
3. Все коды расширяются нулями: `z[cid] = append(z[cid], zeros)`
4. Все проекционные матрицы (W_proj, sector_W) дополняются нулевыми строками
5. Подпространственные доли l_c/l_a/l_m пересчитываются под новую размерность

### 3.3 Сжатие ёмкости (prune_capacity)

Если более 30% измерений имеют активность ниже 2% (мёртвые измерения), они удаляются:

1. Вычисляется `active_frac[dim] = mean(|codes[:, dim]| > 1e-4)`
2. Все измерения с `active_frac < 0.02` исключаются
3. Базис переортогонализируется
4. Все матрицы проекций сжимаются

## 4. Иерархические поля: поле-в-поле (Field-in-Field)

Традиционные VSA используют фиксированные случайные гипервекторы. FCF заменяет их **обучаемыми бинарными проекциями** — локально-чувствительным хешированием (LSH), адаптирующимся к геометрии выученного пространства.

### 4.1 Плоская проекция

```
field_bits[cid] = packbits(sign(z[cid] · W_proj))
где W_proj ∈ ℝ^{L×512} — обучаемая матрица проекции
```

`W_proj` обновляется по правилу Хебба:

```
W_proj += lr · mean( z · sign(z · W_proj) )   (с последующей нормировкой столбцов)
```

### 4.2 Иерархический секторный индекс

Поле организовано как трёхуровневая иерархия:

| Уровень | Бит | Грубость | Число секторов |
|---------|-----|----------|----------------|
| 0 (грубый) | 4 | Крупные кластеры | ~16 |
| 1 (средний) | 10 | Секторы | ~1024 |
| 2 (точный) | 20 | Подсекторы | ~1M |

Каждый уровень имеет собственную матрицу проекции `_sector_W[lvl] ∈ ℝ^{L×bits_lvl}`. Инвертированный индекс `{префикс → список CID}` строится для каждого уровня и перестраивается при каждой синхронизации поля.

### 4.3 Фокальный поиск

Поиск по векторной близости не требует перебора всех 146K концептов:

```
search_in_sector(query_cid, depth=1, k=20):
    key = sector_key(query_cid, depth=1)   — 10-битный префикс
    candidates = sector_index[depth][key]  — O(1) lookup
    for cid in candidates:
        score = cos(query, candidate)
    return top-k
```

Если на текущем уровне недостаточно кандидатов, происходит **прогрессивное уточнение**: поиск начинается с грубого уровня и углубляется при необходимости:

```
focal_refine(query_cid, start_depth=0, target_k=10):
    for depth from 0 to max_depth:
        results = search_in_sector(query_cid, depth, k=target_k×3)
        if enough(results): return results
```

### 4.4 EntityField — рекурсивное семантическое поле

EntityField — единое хранилище для всех сущностей: символов, морфем, слов, предложений, абзацев. Каждая сущность имеет вектор-представление в 2048D и бинарную роль (CHAR, MORPH, WORD, SENT, PARA).

VSA bind/unbind связывают все уровни:

```
V(char)  += bind(V(word), CHAR_ROLE)
V(word)  += bind(V(sent), WORD_ROLE)
V(sent)  += bind(V(para), SENT_ROLE)
```

Unbind(V(entity), role) восстанавливает суперпозицию контекстов: `context = unbind(V(word), WORD_ROLE)` — проекция на уровень предложения.

EntityField использует:
- **LFU-эвикцию** при превышении лимита сущностей
- **word_envelope()** — симметричная проекция контекста на слово
- **modulate()** — STD-модуляция внимания (следы нейромедиаторов)
- **decay(factor=0.999)** — предотвращение неограниченного роста на каждом чекпойнте

### 4.5 Harmonizer — морфемная гармонизация

Harmonizer связывает морфемный уровень с векторными представлениями слов через VSA compose_word / decompose_word.

**compose_word(parts, ctx_vec)** — собирает слово из морфем с контекстной модуляцией корня:

```
root = unbind(ctx_vec, ROOT_ROLE)     # контекстная модуляция корня
word = bind(root, ROOT_ROLE) + Σ bind(morph_i, MORPH_ROLE_i)
```

**decompose_word(v_word)** — разлагает вектор слова на морфемы:

```
morph_i = unbind(v_word, MORPH_ROLE_i)
```

Harmonizer использует:
- **dirty-флаги** — слова, изменившиеся с последней гармонизации
- **slow-start** — постепенное увеличение harm_lr от 0.1 до 1.0 за 5 чекпойнтов
- **обратный индекс morph→word** — предотвращает лавинное распространение
- **preharm checkpoint** — rollback до первой гармонизации
- **morph_drift** — метрика расхождения composed vs actual (на каждом чекпойнте)
- **контекстная модуляция через sent_vec** — encode концепт-вектора (768D) → латентное пространство (2048D) через basis.T

Harmonizer интегрирован в STDP-тренировку через `_harmonize_batch()`: после каждого батча все dirty-слова проходят harmonize с контекстной модуляцией от sentence vector.

## 5. HDC/VSA интеграция

FCF реализует полную алгебру VSA как **резервный механизм**, а не основное представление.

### 5.1 Операции

| Операция | Определение | Назначение |
|----------|-------------|------------|
| **bind** (⊙) | `a * b` (поэлементное умножение) | Кодирование n-грамм |
| **permute** (ρ) | `roll(v, 1)` (циклический сдвиг) | Кодирование позиции |
| **bundle** | `accum = (1−lr)·accum + lr·v` | Накопление n-граммной памяти |
| **unbind** | `context ⊙ memory_repr` | Декодирование запроса |

### 5.2 N-граммная память

Для каждой наблюдаемой n-граммы `(w1..wn)` строится HDC-представление:

```
repr = ρ^{n-1}(v1) ⊙ ρ^{n-2}(v2) ⊙ ... ⊙ vn
```

Оно накапливается в словаре `hdc_memory[prefix_cids]` как скользящее среднее. На каждом STDP-шаге все n-граммы (2..4) текущего предложения обновляют эту память.

### 5.3 Резервное предсказание

Если статистическая n-граммная решётка (SyntaxLattice) возвращает менее 3 кандидатов, активируется HDC-резерв:

```
query = unbind(context_codes, hdc_memory[prefix])
candidates = top-k cos(query, all_codes)
```

Этот сигнал интегрируется в RRF (Reciprocal Rank Fusion — метод обратного рангового слияния) вместе с графовыми, синтаксическими и векторными сигналами.

### 5.4 Групповая алгебра ℤ₈^d — формализация VSA

Все VSA-операции FCF формализованы как **действия групповой алгебры ℝ[G]**, где G = ℤ_{s₁} × ℤ_{s₂} × … × ℤ_{s_d} — прямое произведение циклических групп. Размерность D = 768 факторизуется как `VSAGrid.factorize(768)` = (8, 8, 6, 2).

#### 5.4.1 Базовые операции на группе

| Операция | В плоском пространстве | В групповой алгебре |
|----------|----------------------|---------------------|
| **bind** (⊙) | FFT-HRR: `irfft(rfft(a)·rfft(b))` | Свёртка на G — умножение характеров |
| **hybrid bind** | `α·hrr + (1-α)·ew` | Среднее свёртки и поточечного умножения |
| **unbind** (⊘) | FFT-HRR: `irfft(rfft(c)·conj(rfft(b)))` | Корреляция на G |
| **permute** (ρ) | `roll(v, shift)` | Сдвиг на элемент группы: `(τ_g v)(h) = v(h-g)` |
| **bundle** (+) | `v + u` | Сумма функций на G |
| **convolution** | `smooth_features(v) = k * v` | Group convolution: `(k*v)(g)=Σ_h k(h)·v(g-h)` |

#### 5.4.2 VSAGrid — mixed-radix отображение

Класс `VSAGrid(dim)` факторизует D в произведение малых целых (radix ≤ 8) и задаёт биекцию между плоским индексом [0, D-1] и кортежем ℤ_{s₁} × … × ℤ_{s_d}:

```
VSAGrid(768) → shape = (8, 8, 6, 2)
flat_to_grid(42) → (2, 1, 3, 0)     # ℤ₈ × ℤ₈ × ℤ₆ × ℤ₂
```

Методы `fft_nd` / `ifft_nd` реализуют многомерное FFT через `np.fft.fftn(reshape(vec, shape))`. Это O(D·Σlog s_i) вместо O(D·log D) — выигрыш для больших размерностей.

#### 5.4.3 VSACNN — иерархическая свёрточная VSA

`VSAConvLayer` — multi-scale convolution (gaussian, laplacian, gabor, dog, uniform) → bundle результатов. `VSACNN` — стек таких слоёв с увеличивающимся масштабом, возвращает **пирамиду признаков**.

Без единого learned weight: всё — closed-form VSA-операции на группе.

#### 5.4.4 Zeckendorf-взвешивание

Вес w ∈ [0,7] раскладывается `Zeckendorf(w)` в сумму непоследовательных чисел Фибоначчи:
- 7 = 5 + 2, 6 = 5 + 1, 4 = 3 + 1, 3 = 3

Каждый компонент → bind(vec, scale(sub_vec)), результаты bundle. Вес — не скаляр, а **структура**.

#### 5.4.5 ResidueEncoder — RNS

Числовые значения кодируются через CRT: `value % m` для каждого модуля m ∈ {17, 19, 23, …}, затем bind всех базовых векторов остатков. Позволяет делать арифметику в VSA (add = bundle, mul = bind).

#### 5.4.6 Адаптивное квантование similarity → [0,7]

`_quantize_adaptive(sim, mean, std)` — z-score: `z = (sim - mean) / std`, clipped к [-z_score, z_score], маппинг в [0, 7]. Адаптируется к распределению схожестей в батче — не фиксированная шкала.

#### 5.4.7 Conditional bind — селективное связывание

`_hybrid_bind_masked(a, b, mask, threshold)`: bind только тех измерений, где `mask > threshold`. Остальные остаются нетронутыми. Это **внимание на уровне измерений** — аналог attention head, но без learned projection.

## 6. Fibonacci / Zeckendorf — унифицирующий паттерн

Числа Фибоначчи, Zeckendorf-разложение и золотое сечение — не разрозненные
трюки, а **единый структурный принцип**, пронизывающий все уровни FCF.
Там, где классические архитектуры используют произвольные константы
(depth=6, buffer=10000, lr=0.01, threshold=0.7), FCF использует Fibonacci
как естественную метрику последовательности.

### 6.1 Почему Fibonacci?

Любая операция над последовательностью — это разложение целого числа
(позиции, веса, глубины, размера буфера) на сумму меньших частей.
Zeckendorf («ни одна последовательная пара») даёт:

- **Минимальную длину** — `Zeckendorf(n)` всегда короче любого base-K
  разложения для K < φ (бинарное: 6 термов для n=1000, Zeckendorf: 4)
- **Рекурсивную вложенность** — `F_k = F_{k-1} + F_{k-2}` — каждый
  Fib-шаг — подпоследовательность предыдущего, автоматически
- **Самоподобие** — отношения соседних членов стремятся к φ ≈ 1.618,
  единый масштаб на всех уровнях

### 6.2 Применение по всей архитектуре

| Компонент | Что заменено | Как работает | Эффект |
|-----------|-------------|--------------|--------|
| **Fractal encoding** (#53) | octree base-8 пути | `concept_id → Zeckendorf(id)` — разложение на Fib-числа вместо base-8 цифр | Общий префикс = семантическая близость |
| **Константы** (#54) | γ=0.85, буфер 10K | `γ=1/φ`, `beam_buffer=10946(F₂₁)`, `checkpoint=4181(F₁₉)`, `morph_buffer=2000` | Единая φ-шкала |
| **Расписания** (#55) | eval/decay по эпохам | `lr_cosine_mult=φ`, интервалы 1597, 4181, 10946; hormonal окна F₁-F₄ | Fib-шаги = самоподобные интервалы |
| **Квантование** (#56) | линейные бины | `ZeckendorfQuantizer`: границы бинов 0,1,2,3,5,8,13,21… | Естественное сжатие: редкие числа получают свои бины |
| **Временная память** (#56) | `exp(-dist/τ)` | `TemporalZeckendorf`: Fib-бинары по шагам 1,2,3,5,8,13… | Долгая память без экспоненциального затухания |
| **HDTransformer** (#57) | Zeckendorf-tree | Вес w ∈ [0,7] → `Zeckendorf(w)`: 7=5+2, 6=5+1, 4=3+1 | Вес — структура, не скаляр |
| **VSAAttention** (#57) | Zeckendorf-weighted bind | weight_hv = Fib-роль, bind(weight_hv, value) | Структурное взвешивание вместо scale |
| **Позиционное кодирование** (#57) | `fib_position_shift` | `roll(v, FibonacciUtils.fib_position_shift(t, dim))` | Позиция t кодируется Fib-сдвигом |
| **Subspace доли** (#57) | произвольные | `l_c : l_a : l_m = φ² : φ : 1` | Единая φ-пропорция через все подпространства |

### 6.3 Глубинная причина

Все эти применения — **один и тот же алгоритм**:

```
Zeckendorf(n) → [F_k, F_{k-2}, …, F_1]
  ↓
Для каждого Fib-числа: bind(hv_n, role_{F_i}) или bundle(weighted_vec)
  ↓
Результат: сумма/связка Fib-компонентов с единой алгеброй
```

Не важно, что такое `n`:
- ID концепта → Zeckendorf → путь в fractal encoding
- Позиция токена → Zeckendorf → Fib-сдвиг
- Вес внимания → Zeckendorf → структурный bind
- Временной шаг → Zeckendorf → TemporalZeckendorf бинар
- Размер буфера → Zeckendorf → рекурсивное расширение
- Интервал расписания → Fib-число → самоподобный шаг

**Fibonacci — не константы, а алгебра последовательностей.**

### 6.4 Что изменилось (до/после)

| Аспект | До (октантные/произвольные константы) | После (Fibonacci/Zeckendorf) |
|--------|--------------------------------------|------------------------------|
| Пути концептов | `octree(id) → [d₀, d₁, …, d₆]` base-8 | `zck(id) → [Fₓ, F_y, …, F_z]` Fib-sum |
| γ (learning rate) | 0.85 | 1/φ ≈ 0.618 |
| Beam buffer | 10 000 | 10 946 (F₂₁) |
| Checkpoint interval | 5000 | 4181 (F₁₉) |
| Morph buffer | 2000 | 2000 (F₁₈) |
| LR cosine mult | π | φ ≈ 1.618 |
| Eval interval | каждые 5000 | 1597 (F₁₇) |
| Decay interval | каждые 2500 | 4181 (F₁₉) |
| Hormonal L1 | каждые 100 | 1 (F₁) |
| Hormonal L2 | каждые 500 | 3 (F₄) |
| Quantization | линейные бины 0..7 | Fib-бинары [0,1,2,3,5,8,13] |
| Temporal memory | `exp(-dist/τ)` | `TemporalZeckendorf(dist)` |
| Subspace ratios | l_c=0.6, l_a=0.25 | l_c:l_a:l_m = φ²:φ:1 |
| Position enc | произвольный shift | `fib_position_shift(t)` |

## 7. RRF-слияние: как принимается решение

При генерации следующего токена все источники знаний объединяются через взвешенное слияние обратных рангов:

| Источник | Вес | Что даёт |
|----------|-----|----------|
| Граф связей | 0.7 | Семантическая близость через граф |
| N-граммы (синтаксис) | 0.15/k | Статистическая вероятность |
| Векторная близость (сектор) | 0.15 | Геометрическая близость на сфере |
| HDC n-gram резерв | 0.10 | VSA-декодирование при нехватке данных |
| Beam-score (Transition Manifold) | 0.05 | Направление перехода на известном луче |
| Априорная частота | 0.02 | Частотный приоритет |
| Гомеостатический буст | ×1.3 | Усиление недоиспользованных концептов |

Дополнительно:
- **Бонус центроида интента**: концепты, умеренно близкие к запросу (cos ~0.5), получают усиление
- **Блокировка n-грамм**: повторяющиеся n-граммы блокируются
- **MMI-штраф**: штраф за слишком вероятные токены (избегание тривиальности)

## 8. Transition Manifold — паутина STDP-переходов

Transition Manifold — дополнение к STDP, обучающееся на переходах между концептами.

### 7.1 Векторы переходов

Каждый раз, когда токен A предшествует B, строится вектор перехода:

```
T = unbind(v_B, v_A)    — VSA-алгебра: направление от A к B
```

Эти векторы копятся в **кольцевом буфере** (10K записей). При достижении лимита самые старые вытесняются.

### 7.2 Кластеризация в лучи

Из буфера жадным VSA-бандлом формируются **лучи** (до 100):

```
beam = mean(T_i for T_i in cluster)    — центроид луча
beam = normalize(beam)
```

Кластеризация — однопроходная: каждый новый T либо добавляется к ближайшему лучу (cos > 0.7), либо начинает новый. После каждого батча лучи перестраиваются с перемешиванием (shuffle), чтобы избежать систематического смещения.

### 7.3 Точки врезки

Transition Manifold имеет три точки врезки в основной конвейер:

1. **Beam-pull в STDP** (CPU + GPU путь): после scatter_add каждый обновлённый концепт слабо притягивается к ближайшему лучу:

   ```
   z_c[cid] += beam_pull_strength * beam_z    (0.01 — мягкое притяжение)
   ```

2. **Beam-score в RRF** (`_branch`): score кандидата модулируется тем, лежит ли переход «текущий → кандидат» на известном луче:

   ```
   beam_score = cos(T(candidate), nearest_beam) * branch_conf_scale
   ```

3. **Морф-уровень** (`_harmonize_batch`): отдельный TransitionManifold для морфемных переходов — `T = unbind(morph_i+1, morph_i)`.

### 7.4 Конфигурация

Все параметры — через FCFConfig: `beam_buffer_size` (10K), `max_beams` (100), `beam_similarity_threshold` (0.7), `beam_pull_strength` (0.01), `branch_conf_scale` (0.5), `morph_manifold_buffer` (2000).

## 9. Дополнительные модули (dead code, default OFF)

Три экспериментальных модуля, интегрированных в конвейер, но отключенных по умолчанию (флаги FCFConfig):

### 8.1 MorphSTDP

Наблюдает за морфемными биграммами внутри слова: STDP-притяжение между соседними морфемами. Работает в `_harmonize_batch` после char↔word bind. Параметры: `cohesion` (сила притяжения), `discover_every` (частота обновления).

### 8.2 VSAAttention

Механизм внимания на VSA-операциях: `weights = softmax(sim(Q, K))`, `output = Σ bind(weight_hv_i, V_i)` через Zeckendorf-взвешивание. Используется как дополнительный RRF-сигнал в `_branch`.

### 8.3 HDTransformerLayer

Однослойный VSA-native трансформер: Q/K/V — permute контекстных векторов, forward — bundle с skip-connection. Интегрирован в `_train` после негативной выборки.

## 10. Дистилляция знаний Qwen

Внешняя модель (Qwen 3.4B) используется не как генератор, а как источник семантических связей.

### 9.1 Процесс

1. На корпусе из 30М символов предвычисляются косинусные близости между всеми парами токенов через эмбеддинги Qwen (слои 12–24).
2. Пары с count≥3 проходят фильтр: 20.6M → 1.53M высоконадёжных пар.
3. При STDP-тренировке каждая пара токенов получает LR-модулятор:

```
factor = get_factor(cos_sim):
    cos < 0.15 → 1.0 (нейтрально)
    0.15 ≤ cos < 0.20 → 1.0 — (cos-0.15)/0.05·0.15 (линейное отталкивание)
    cos ≥ 0.20 → 1.0 + cos·0.3 (кап 1.5)
```

### 9.2 Инвертированный кластерный потенциал

Редкие концепты с высокой ошибкой (CE) получают усиление кластерного потенциала до 1.2. Хорошо изученные — снижение до 0.8. Механизм противодействует эффекту «богатые становятся богаче».

Процесс обучения подстраивается под состояние модели:

- **Оптимизатор параметров** отслеживает тренды косинуса, перплексию, обновления концептов; на лету настраивает скорость обучения, PMI-ключи, интенсивность выборки

## 15. Защита от коллапса и переполнения

### 14.1 Collapse Guard: авто-усиление латерального торможения

Средний косинус между случайными концептами (cos_mean) отслеживается на каждом чекпойнте. Если он превышает 0.08 — ранний признак коллапса пространства:

```
scale = 1.0 + (cos_mean - 0.08) × 50
inh_strength = clamp(default × scale, min, max)
```

При cos_mean = 0.09 сила торможения ×1.5, при 0.12 ×3.0. Если косинус падает ниже 0.04 — сила возвращается к базовой. Это предотвращает «тихий коллапс», когда все векторы медленно стягиваются к общему центру из-за STDP и центроидного притяжения.

### 14.2 HDC n-gram memory: LRU-кэш

Накопление HDC-представлений всех биграмм может привести к переполнению памяти (до 11 GB в худшем случае). Решение:

- `hdc_memory_max = 50000` — жёсткий лимит записей
- FIFO-очередь: при превышении лимита вытесняется самая давняя запись
- При доступе к записи через `hdc_predict` она перемещается в конец очереди
- Каждый STDP-батч добавляет не более длины предложения новых биграмм

Это гарантирует, что HDC-память занимает не более 50K × 2048 × 4B ≈ 400 MB, с автоматическим вытеснением редко используемых n-грамм.

### 14.3 Rescore с батчированием

Self-paced curriculum (`_rescore_lines`) теперь обрабатывает строки группами по 256, с прогресс-индикацией каждые 5000 строк. Это улучшает utilisation GPU и даёт прозрачность на больших корпусах.

### 14.4 VRAM-безопасность

На GPU с <4GB памяти:
- `--no-morpheme-field` — отключает морфемное поле
- `--no-hebbian-field` — отключает хеббово обновление полей
- `_codes_t` (bf16 V×L, 598 MB) — удалён как неиспользуемый
- `_ema_vecs_t` — на CPU, синхронизируется с GPU по необходимости
- `fb_overlaps` — чанкованный расчёт (topk вместо полной V×V матрицы)
- `_codes_master_t` — bf16 (был fp32, вдвое меньше)

## 16. Нейроморфное соответствие

FCF — единственная известная языковая модель, принципиально совместимая с нейроморфными процессорами (Intel Loihi 2, IBM TrueNorth, российские разработки НИИСИ, «Модуль»/Байкал-Н, Курчатовский институт «Алкуда»). Совместимость не случайна — архитектура FCF спроектирована без единого требования, которое нейроморфное «железо» не может выполнить нативно.

### 15.1 Только локальные правила (никакого backprop)

FCF не использует обратное распространение. Все механизмы пластичности — STDP, Hebbian update, L1 soft-thresholding, латеральное торможение — работают исключительно на локально доступной информации: состоянии пре-синаптического и пост-синаптического нейрона.

На кремнии: мемристорный кроссбар (матрица резистивных элементов) физически реализует STDP. Проводимость мемристора меняется пропорционально напряжению на его выводах: `ΔG = V_pre · V_post`. Это не эмуляция — это **физический закон**, выполняющийся на уровне материала. Обратное распространение такой физической интерпретации не имеет.

### 15.2 Аддитивные обновления = синаптические события

Базовая операция FCF — `code[cid] += lr · Δ` (scatter_add разреженного вектора). На GPU это атомарная операция с блокировкой памяти (сотни нс, единицы нДж). На нейроморфном чипе:

1. Пре-синаптический нейрон генерирует спайк
2. Спайк достигает синапса, проводимость меняется на ΔG
3. Пост-синаптический нейрон накапливает заряд

Это **одно физическое событие**: ~1 пикоджоуль против ~1 нДж на GPU и ~1 мкДж на CPU.

### 15.3 Событийная природа

FCF обновляет только концепты, участвовавшие в текущем предложении (~10–50 из 146K). 95% словаря простаивает. Нейроморфный чип потребляет энергию **только при спайке** — в покое микроамперы утечки. На GPU простаивающие данные всё равно занимают память и шину.

### 15.4 Разреженность 8% и динамическая размерность

L1 удерживает плотность кода ~8% (160 активных из 2048). Аналоговые мемристорные матрицы имеют максимальную точность при малом числе одновременных активаций на ряд — 8% идеальная рабочая точка. `grow_capacity()` / `prune_capacity()` — нейрогенез и прунинг на физическом уровне: выделение/освобождение рядов синапсов без перекомпиляции.

### 15.5 Секторный индекс = Content-Addressable Memory

Трёхуровневое поле (4+10+20 бит) — аппаратный CAM. Поиск по сектору: битовая маска подаётся на шину адреса, все ячейки одновременно сравнивают тег — O(1) независимо от размера словаря. Российские проекты (Курчатовский институт «Алкуда», НИИСИ) проектируют CAM как аппаратный примитив первого класса — секторный индекс FCF алгоритмически идентичен их предложениям.

### 15.6 HDC/VSA алгебра как система команд

bind(⊙), permute(ρ), bundle(+) — на чипе с VSA-микрокодом это один инструкционный цикл. Резервный n-граммный unbind (при нехватке статистических данных) выполняется за O(1), а не O(V).

### Российские разработки и FCF

| Разработчик | Технология | Точка совпадения с FCF |
|-------------|------------|------------------------|
| **НИИСИ РАН** | Event-driven процессоры, мемристоры | STDP как физический процесс, разреженная маршрутизация |
| **«Модуль» (Байкал-Н)** | Нейроускоритель с аппаратным STDP | Аппаратный scatter-add, per-concept EMA как состояние нейрона |
| **Курчатовский институт («Алкуда»)** | Мемристорные CAM, бинарные сети | Секторный индекс = CAM, W_proj = проводимости кроссбара |
| **МИЭТ / ИТМиВТ** | In-memory computing, аналоговые матрицы | 8% разреженность — оптимум для аналоговых кроссбаров |
| **НПЦ «Элвис»** | Параллельные процессоры для sparse-векторов | HDC-память как распределённый CAM |

### Резюме

FCF — единственная известная архитектура уровня «язык», где каждое вычислительное требование совпадает с возможностями нейроморфного «железа»: никакого backprop, только локальные правила, аддитивные обновления как физические синаптические события, событийная модель исполнения, разреженность 8%, динамическая ёмкость, CAM-совместимый секторный индекс, VSA-алгебра как система команд.

GPU для FCF — временная платформа.

## 17. Инфраструктура конфигурации

### 16.1 FCFConfig — единый источник истины

Все константы, ранее разбросанные по модулям, централизованы в `fcf_config.py`:

- Размерности: `dim` (768), `latent_dim` (2048), `n_anchors`
- STDP: lr, context_window, neg_samples, pmi_gate
- Transition Manifold: beam_buffer_size, max_beams, beam_pull_strength
- Harmonizer: harm_lr, morph_lr, n_iter, damping
- EntityField: max_entities, dim_fallback
- Специальные токены: BOS=1, EOS=2, PAD=0, UNK=0
- FormulaCoefficients: все коэффициенты из `hormonal_system.py`

```
config = FCFConfig()
dim = config.dim          # 768
latent_dim = config.latent_dim  # 2048
```

### 16.2 Hot-reload

`FCFConfig.reload()` перечитывает файл без перезапуска процесса. Подписка через `subscribe(fn)` — все зависимые модули получают уведомление через `notify_observers()`.

### 16.3 Param cascade — живые defaults

`Param` хранит ссылку на `ParamDef` из `parameter_optimizer.py`. `toward_default()` перечитывает default из ParamDef, а Param в свою очередь может читать его из FCFConfig. Это обеспечивает каскадное обновление: изменение конфига → обновление ParamDef → обновление Param → обновление всех точек использования.

### 16.4 SeedRegistry — детерминизм

Все генераторы случайных чисел централизованы в `SeedRegistry`. Вместо `hash(key) % (2**31-1)` или `RandomState(42 + growths)`:

```
seed = SeedRegistry.get('char_init')      # master + hash('char_init')
seed = SeedRegistry.get(f'char_init_{cp}') # per-concept variant
```

Детерминизм: одинаковый master-сид → одинаковые результаты независимо от порядка вызовов. Это критично для воспроизводимости на нейроморфном железе, где нет глобального состояния.

### 16.5 FormulaCoefficients

`hormonal_system.py` преобразован в `FormulaCoefficients` — словари коэффициентов для формульных констант (ACh, NE, DA, 5HT; STDP-curve parameters). Все коэффициенты — в `FCFConfig.formula`, доступны через `FCFConfig().formula`.

## 19. Мотивация

FCF — исследовательский проект на стыке двух традиций: **нейро-символического ИИ** и **гипермерных вычислений (HDC/VSA)**.

Основной вопрос:

> **Можно ли построить семантическое пространство без градиентного спуска — на одних локальных правилах пластичности, обучаемой полевой проекции и саморганизующемся фрактальном коде?**

Если да — это открывает путь к полностью интерпретируемым языковым моделям, где:
- Каждый вектор — **физический факт** о статистике совместной встречаемости
- Каждый бит поля — **выученная семантическая гиперплоскость**
- Каждая граница сектора — **обнаруженное понятийное различие**
- Ёмкость модели **растёт с её знаниями** и **сжимается при бездействии**
- VSA-переходы **явно моделируют динамику** между концептами

Никаких латентных активаций. Никаких неинтерпретируемых глубоких сетей. Никакой фиксированной размерности.
