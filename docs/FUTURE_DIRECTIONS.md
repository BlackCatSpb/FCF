# Future Directions

Архитектурные идеи, выходящие за рамки текущего плана, но естественно
ложащиеся на VSA+STDP-фундамент FCF.

---

## Принцип: Fibonacci как design pattern

Рекурсивная вложенность (ряды Фибоначчи, Zeckendorf, золотое сечение)
проявляется везде, где есть иерархия без жёстких границ. Рекомендация:
вместо произвольных констант использовать Fib-ограничения:

```
Вместо:   depth=6,  buffer=10000,  lr=0.01,  threshold=0.7
Спрашивать: «какое число Фибоначчи здесь естественно?»
```

Текущие кандидаты на Fib-замену перечислены ниже в соответствующих
разделах. Общий принцип: Fib-архитектура даёт самоподобие
(иерархическую вложенность) бесплатно — как свойство выбранных чисел.

## 1. Активное любопытство (Curiosity-driven learning)

**Идея:** Модель сама определяет, какие концепты она «не понимает», и
инициирует целенаправленное чтение для заполнения пробелов.

**Метрика неопределённости:**
```
uncertainty(c) = 1.0 - max(cos(v_c, v_neighbor))
```
Если у концепта нет близких соседей на гиперсфере — он одинок, и модель
должна понять, почему. Если соседей слишком много — концепт, возможно,
слишком общий и требует расщепления.

**Механизм:**
1. Вычисление uncertainty для всех концептов (O(V) — легко)
2. Пороговая активация: если uncertainty > T и freq > min_freq, концепт
   помечается для «сканирования любопытством»
3. Сканирование: перечитать контексты, где встречался концепт, с повышенной
   скоростью STDP
4. Опционально: расщепить подпространство концепта, если uncertainty не
   падает после сканирования

**Статус:** Идея. Фундамент готов (TransitionManifold, beam_score,
Harmonizer). Нет метрики неопределённости и контура обратной связи.

---

## 2. Активное забывание и консолидация (Sleep / Consolidation)

**Идея:** Имитация сна — периодическая фаза, где модель:
- Сливает почти идентичные концепты (cos > 0.98)
- Удаляет концепты с нулевой частотой (мусор)
- Усиляет важные переходы (prune слабые, boost сильные)

**Биологическая аналогия:** Во время сна гиппокамп «проигрывает» дневные
события, перенося их в кору. В FCF — offline-фаза, где TransitionManifold
консолидируется в SyntaxLattice.

**Статус:** Идея. Есть примитивы (beam buffer, syntax_lattice, concept
pruning). Нет планировщика фаз сна/бодрствования.

---

## 3. Иерархия временных масштабов (Temporal Hierarchy)

**Идея:** Несколько экземпляров TransitionManifold с разными окнами STDP:
- L1: 2-3 токена — синтаксис (есть сейчас)
- L2: 10-20 токенов — дискурс
- L3: 100+ токенов — тема/документ

Каждый уровень обучает концепты своего масштаба. Верхние уровни получают
вход от нижних через VSA-bundle.

**Статус:** Идея. Единственный TransitionManifold есть (L1). Нужны L2, L3
и механизм «вертикальной» VSA-связи между уровнями.

---

## 4. Кросс-модальная интеграция

**Идея:** Изображение → CLIP/ViT → e5-like эмбеддинг → VSA-bind с текстовыми
концептами. Те же STDP-правила работают кросс-модально.

**Важность:** FCF — единственная архитектура, где текст и изображение могут
разделять общее гиперсферное пространство без дополнительных проекций.

**Статус:** Идея. Ничего не реализовано. Фундамент: VSA-алгебра
модально-независима.

---

## 5. Memristor-native режим (Binary HD)

**Идея:** Текущие fp32-векторы неэффективны на мемристорных кроссбарах.
Добавить режим Binary HD:
- bind = XOR
- bundle = мажоритарное голосование
- расстояние = Hamming

Это позволит запускать FCF на существующих мемристорных прототипах без
FPU.

**Статус:** Идея. Весь VSA-фреймворк уже абстрагирован (basis, bind,
bundle). Нужен BinaryMode с переключением на лету.

---

## 6. Эмерджентная иерархия концептов (Knowledge Accretion)

**Развитие идеи любопытства.** Модель не просто заполняет пробелы, а
строит иерархию:

1. **Грубый образ** (уровень 0, 128D подпространство) — «собака = животное»
2. **Категоризация** (уровень 1, 256D) — «овчарка, такса, пудель — собаки»
3. **Детализация** (уровень 2, 512D) — «немецкая овчарка выведена в XIX в.»
4. **Полнота** (уровень 3, 768D) — полный семантический профиль

Каждый уровень — это подпространство латентного кода. Грубые признаки
(z_c, ~60%) замерзают быстро. Детальные (z_m, ~15%) продолжают уточняться.

**Текущее состояние:** Подпространства уже есть (z_c, z_a, z_m), но они
не используются как уровни детализации. Нужна стратегия «замерзания»
нижних уровней и стратегия расщепления при переполнении.

## 7. Резонансная сознательная обработка (Beam Resonance)

**Идея:** Когда beam_score стабилизируется на высоком значении через
несколько шагов STDP, это функциональный аналог «осознанной мысли» —
устойчивый паттерн VSA-связанных концептов.

Можно использовать как:
- Сигнал для чекпойнта: «модель пришла к устойчивому выводу»
- Триггер для консолидации: запомнить整个 паттерн как единый концепт
- Метрику «понимания»: чем выше и стабильнее beam_score, тем глубже
  модель обработала контекст

**Статус:** Идея. Beam_score и RRF-сигнал есть (TransitionManifold +
crystal_generator). Нет метрики стабильности во времени.

**Важное ограничение:** Режим реального времени (inference + beam resonance)
**невозможен на CPU/GPU** — последовательная архитектура не даёт параллельной
вспышки. Резонанс должен быть физическим свойством мемристорного кроссбара:
векторы концептов — напряжения на строках, ток bundle — сумма по столбцам
(закон Кирхгофа), проверка beam_score — параллельное сравнение за один такт.
На фон-Неймановской архитектуре осознание — симуляция. На мемристоре —
свойство схемы.

Вывод: разделить режимы:
- **Обучение** (STDP) — CPU/GPU/мемристор, накопление весов
- **Осознание** (resonance) — только мемристор, параллельная вспышка

Архитектурно (TransitionManifold + beam_score) это разделение уже
поддерживается. Железо — следующий шаг.

## 8. Само-контролируемый curriculum (Self-supervised Curriculum)

**Развитие любопытства до уровня обучения.** Вместо последовательного
чтения корпуса, модель выбирает следующие строки для максимизации
reduction of uncertainty:

```
next_line = argmax(uncertainty_reduction(line | current_state))
```

Где uncertainty_reduction — ожидаемое снижение суммы неопределённостей
всех концептов после STDP на этой строке.

Это превращает обучение из пассивного в активное: модель сама решает,
что ей читать дальше, исходя из текущего состояния знаний.

**Статус:** Идея. Нет метрики uncertainty reduction. Есть весь
STDP-пайплайн для вычисления эффекта от одной строки.

## 9. Fibonacci-дизайн констант (Fibonacci as Design Pattern)

**Идея:** Заменить произвольные константы в архитектуре на числа
Фибоначчи, дающие рекурсивную вложенность как свойство выбранных
ограничений.

**Текущие кандидаты:**

| Компонент | Сейчас | Fib-замена | Эффект |
|---|---|---|---|
| STDP learning rate | `lr=0.01` константа | `lr(t) = lr₀ × φ^{-t}` | Быстрое обучение новому, стабильность старого |
| Beam buffer size | 10000 (произвольно) | `F_{k+1} = F_k + F_{k-1}` | Рекурсивное расширение при переполнении |
| Checkpoint intervals | 5k равномерно | 1k, 2k, 3k, 5k, 8k, 13k, 21k… | Откат на предыдущий уровень детализации |
| Cluster thresholds | `thresh=0.7` | `thresh_k = thresh₀ × φ^{-k}` | Чем выше уровень, тем точнее кластеризация |
| Fractal encoding | octree base-8 | Zeckendorf-пути | concept_id = Fib-разложение, общий префикс = семантическая близость |

**Fractal encoding — ключевой кандидат.** Вместо октантных путей
(произвольная base-8 глубина) использовать разложение concept_id
по Zeckendorf:

```
cid = 12345
→ octree:  [1, 7, 2, 3, 1, 5]   (6 уровней, без связи между соседними id)
→ Zeck:    [10946, 1597, 610, 144, 34, 13, 1]  (вложенность = префикс)
```

Два концепта с общим Zeckendorf-префиксом семантически ближе — это даёт
естественную иерархию без дополнительного кода.

**Статус:** Идея. `fibonacci_utils.py` и Zeckendorf в VSAAttention уже
есть. Fractal encoding пока на octree.
