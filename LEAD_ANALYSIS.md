# FCF — Lead Developer Analysis (2026-06-11)

## Executive Summary

FCF — это живая система с 21 исправленным багом, но с фундаментальной архитектурной проблемой: **векторы не раздвигаются**. После 145K строк (7.5h) обучения:
- vecPPL=27990 (vs random 32158) — всего 13% улучшения
- vacc@1=0.000 — **вектор никогда не угадывает токен**
- cos=0.0003±0.0532 — почти как инициализация

Причина не в багах — мы их пофиксили. Причина в дизайне обучения.

---

## 1. Архитектурная проблема №1: «Тёплый душ» (только Hebbian, нет repulsion)

**По умолчанию**: `neg_samples=0`, lateral inhibition с threshold=0.25 при std=0.053 — почти никогда не срабатывает.

**Что происходит**: STDP тянет все со-встречающиеся векторы ДРУГ К ДРУГУ. Репульсии нет. Векторы не раздвигаются — только слегка дрейфуют через fluctuation (noise=0.003, decay=0.9995 → эффект за 72 вызова: распад 3.5%, накопленный шум 0.025).

**Доказательство**: cos=0.0003±0.0532 — это почти random init (0.0001±0.0502). Векторы не коллапсируют в одну точку (fluctuation + разные контексты удерживают), но и не формируют кластеры. Это «диффузный газ», а не семантическое пространство.

**Решение:**
```python
# 1. Включить negative sampling по умолчанию
neg_samples = 1  # сейчас 0

# 2. Снизить порог lateral inhibition
inh_threshold = 0.10  # при std=0.053, ~3% пар превысят это
```

---

## 2. Архитектурная проблема №2: STDP учит не тому

STDP сближает векторы токенов, которые встретились в окне ±2. Проблема: в окне ±2 большинство пар — **случайные**, не семантические. «Князь» и «Андрей» — да. «Князь» и «и» — нет.

Из 8.7M STDP-апдейтов за обучение, возможно, только 10-20% приходятся на реально значимые пары. Остальное — шум.

**Решение:** Использовать PPMI для отбора пар вместо равномерного gate.
```python
# Тянуть только пары с PMI > 0
if pmi_gate and pmi_w < pmi_gate_min:
    continue  # skip weak pairs
```

---

## 3. Архитектурная проблема №3: vacc@1=0.000 и что с этим делать

**Причина**: вектор скоринг в evaluate — это `cos(prev_vec, candidate_vec)`. На единичной сфере все векторы распределены почти равномерно (std=0.053). Максимальный cosine между random точкой и 32K другими — ~0.20. У правильного токена вектор такой же «случайный» как и все остальные.

**Но:** acc@1=0.106 — полный скоринг (PMI + ngram + vector) работает в 30 раз лучше random. Это значит, PMI и ngram уже содержат информацию. Векторы — шум к ним.

**Что реально поможет vacc@1:**
1. **Больше данных** — 500K+ строк, чтобы STDP сделал >1000 обновлений на токен
2. **Явная контрастивная цель** — не STDP, а contrastive loss с правильными негативами
3. **Отказ от vacc@1 как метрики** — для 32K классов top-1 точность по одному только cosine — нереалистична

## 6. Почему система всё-таки работает

Даже при vacc@1=0.000, генерация даёт осмысленный текст: «князь великий московский», «любовь и отношению». Это потому что:
- **PMI + ngram** работают (накоплено 6.5M ngram-префиксов)
- **BMSSP-EVA граф** находит пути (1.9M connections, PPMI взвешены)
- **Бим-серч** с RRF fusion комбинирует сигналы

Векторы дают малый вклад, но граф и ngram уже делают генерацию. Улучшение векторов — это improvement, а не необходимость.

## 7. Что ответить координатору

> Обучение показало, что текущая схема (STDP без репульсии) не создаёт осмысленного векторного пространства — векторы остаются «случайным газом» с cos~0. Причина: нет расталкивания. Lateral inhibition не срабатывает (threshold выше 4σ), negative sampling выключен по умолчанию. 
>
> Для исправления: (1) neg_samples=1, (2) inh_threshold=0.10, (3) PPMI-фильтр пар. После этого — повторное обучение на книгах (500K+ строк).
> 
> Параллельно: чиним reset_fractal.py, обновляем requirements.txt, ленивую загрузку lattice для быстрых тестов.
