# FCF — Фрактальное Когнитивное Поле

*Нейро-символическая модель языка на саморганизующейся гиперсфере.*  
*Никаких трансформеров. Никакого обратного распространения. Никакого градиентного спуска.*

---

## 1. Представление знаний: от токена к вектору

Каждый токен SentencePiece BPE (146K словаря) является **концептом** — автономной единицей знания, представленной точкой на единичной гиперсфере в 768-мерном пространстве.

### 1.1 Двухуровневое кодирование

Концепт хранится как пара `(латентный_код, вектор)`:

```
z ∈ ℝ^{L}     — латентный код (разреженный, подпространственно-расщеплённый)
v ∈ 𝕊^{D-1}  — единичный вектор на гиперсфере (D = 768)
v = normalize(z · B)  где B ∈ ℝ^{L×D} — ортонормированный базис (общий для всех)
```

Такое разделение даёт:
- **Код** — внутреннее представление, доступное для пластичности
- **Базис** — общая система координат, единая для всего поля
- **Вектор** — внешнее представление, используемое для сравнения и поиска

### 1.2 Подпространственно-кинетическое расщепление

Латентный код разделён на три функциональных подпространства:

| Подпространство | Доля | Функция | Пластичность |
|---|---|---|---|
| `z_c` (content) | ~60% | Семантическая идентичность | Медленная (L1-регуляризована) |
| `z_a` (attention) | ~25% | Контекстуальное поведение | Быстрая |
| `z_m` (meta) | ~15% | Морфологическая / грамматическая форма | Средняя |

Градиенты проецируются в пространство кода, маскируются по подпространствам, и каждое подпространство обновляется со своей скоростью. Это предотвращает катастрофическое забывание: содержание концепта остаётся стабильным, в то время как контекстуальная активность адаптируется быстро.

## 2. Пластичность: как поле учится

Обратное распространение заменено пятью локальными механизмами пластичности, работающими непосредственно с векторами концептов.

### 2.1 STDP (Spike-Timing-Dependent Plasticity)

Если токен A предшествует токену B в тексте, латентный код B сдвигается к коду A. Величина притяжения модулируется:

- **PMI (Pointwise Mutual Information)** — пары ниже порога отсекаются
- **Вес расстояния** — ближайшие токены влияют сильнее
- **Частотный вес** — редкие токены получают пропорционально более сильные обновления
- **Qwen-фактор** — предвычисленный семантический сигнал от Qwen модулирует LR каждой пары (усиление/отталкивание/нейтрально)
- **Полевой ключ** — межсекторные пары тормозятся

Все пары микробатча обрабатываются одной GPU-операцией scatter_add.

### 2.2 Негативная выборка

Случайные концепты отталкиваются от каждого обновлённого. Сила отталкивания взвешивается ошибкой предсказания концепта: чем хуже модель его знает, тем сильнее регуляризация. Полевые ключи отфильтровывают недопустимые негативы.

### 2.3 Контрастивная цель

Жёсткий майнинг среди top-K ближайших концептов. Похожие, но не встречающиеся вместе и не связанные полем — разносятся. Межполевые пары (разные секторы) отталкиваются агрессивно; внутриполевые — мягко, сохраняя кластерную структуру.

### 2.4 Латеральное торможение

Все обновлённые в батче концепты отталкиваются по геодезической сферы. Предотвращает коллапс: если все векторы станут идентичными, вся информация потеряна. Реализовано через риманов градиент.

### 2.5 Центроидное притяжение

Все токены предложения слабо притягиваются к общему центру. Функционирует как регуляризатор уровня предложения.

## 3. Динамическая размерность: саморегуляция ёмкости поля

Поле не имеет фиксированной размерности. Ёмкость автоматически растёт и сжимается в зависимости от плотности знаний.

### 3.1 L1-регуляризация на подпространство z_c

Каждый концепт individually отслеживает свою плотность — долю активных компонент в `z_c`:

```
density(cid) = mean(|z_c[cid]| > 1e-4)
```

L1-регуляризация стремится удержать плотность каждого концепта около 8%:

```
strength = l1_lambda[cid] · max(0, 1.0 — CE · 2.0)
z_c = sign(z_c) · max(0, |z_c| — strength)
```

- Высокая ошибка предсказания (CE) → слабая L1 → код плотнее
- Низкая ошибка → сильная L1 → код разреженнее

Каждый концепт имеет свой `l1_lambda[cid]`, который адаптируется каждые 2 эпохи.

### 3.2 Рост ёмкости (grow_capacity)

Когда средняя плотность по всем концептам превышает 15%, поле автоматически расширяется:

1. Генерируются новые ортогональные базис-векторы (QR-разложение)
2. Базис растёт: `B ∈ ℝ^{L×D} → B ∈ ℝ^{L'×D}` (L' = L × 1.5)
3. Все коды расширяются нулями: `z[cid] = append(z[cid], zeros)`
4. Все проекционные матрицы (W_proj, sector_W) дополняются нулевыми строками
5. Подпространственные доли l_c/l_a/l_m пересчитываются под новую размерность

### 3.3 Сжатие ёмкости (prune_capacity)

Если более 30% измерений имеют активность ниже 2% (мёртвые измерения), они удаляются:

1. Вычисляется `active_frac[dim] = mean(|codes[:, dim]| > 1e-4)`
2. Все измерения с `active_frac < 0.02` исключаются
3. Базис переортогонализируется
4. Все матрицы проекций сжимаются

## 4. Иерархические поля: поле-в-поле (Field-in-Field)

Традиционные VSA используют фиксированные случайные гипервекторы. FCF заменяет их **обучаемыми бинарными проекциями** — локально-чувствительным хешированием (LSH), адаптирующимся к геометрии выученного пространства.

### 4.1 Плоская проекция

```
field_bits[cid] = packbits(sign(z[cid] · W_proj))
где W_proj ∈ ℝ^{L×512} — обучаемая матрица проекции
```

`W_proj` обновляется по правилу Хебба:

```
W_proj += lr · mean( z · sign(z · W_proj) )   (с последующей нормировкой столбцов)
```

### 4.2 Иерархический секторный индекс

Поле организовано как трёхуровневая иерархия:

| Уровень | Бит | Грубость | Число секторов |
|---------|-----|----------|----------------|
| 0 (грубый) | 4 | Крупные кластеры | ~16 |
| 1 (средний) | 10 | Секторы | ~1024 |
| 2 (точный) | 20 | Подсекторы | ~1M |

Каждый уровень имеет собственную матрицу проекции `_sector_W[lvl] ∈ ℝ^{L×bits_lvl}`. Инвертированный индекс `{префикс → список CID}` строится для каждого уровня и перестраивается при каждой синхронизации поля.

### 4.3 Фокальный поиск

Поиск по векторной близости не требует перебора всех 146K концептов:

```
search_in_sector(query_cid, depth=1, k=20):
    key = sector_key(query_cid, depth=1)   — 10-битный префикс
    candidates = sector_index[depth][key]  — O(1) lookup
    for cid in candidates:
        score = cos(query, candidate)
    return top-k
```

Если на текущем уровне недостаточно кандидатов, происходит **прогрессивное уточнение**: поиск начинается с грубого уровня и углубляется при необходимости:

```
focal_refine(query_cid, start_depth=0, target_k=10):
    for depth from 0 to max_depth:
        results = search_in_sector(query_cid, depth, k=target_k×3)
        if enough(results): return results
```

## 5. HDC/VSA интеграция

FCF реализует полную алгебру VSA как **резервный механизм**, а не основное представление.

### 5.1 Операции

| Операция | Определение | Назначение |
|----------|-------------|------------|
| **bind** (⊙) | `a * b` (поэлементное умножение) | Кодирование n-грамм |
| **permute** (ρ) | `roll(v, 1)` (циклический сдвиг) | Кодирование позиции |
| **bundle** | `accum = (1−lr)·accum + lr·v` | Накопление n-граммной памяти |
| **unbind** | `context ⊙ memory_repr` | Декодирование запроса |

### 5.2 N-граммная память

Для каждой наблюдаемой n-граммы `(w1..wn)` строится HDC-представление:

```
repr = ρ^{n-1}(v1) ⊙ ρ^{n-2}(v2) ⊙ ... ⊙ vn
```

Оно накапливается в словаре `hdc_memory[prefix_cids]` как скользящее среднее. На каждом STDP-шаге все n-граммы (2..4) текущего предложения обновляют эту память.

### 5.3 Резервное предсказание

Если статистическая n-граммная решётка (SyntaxLattice) возвращает менее 3 кандидатов, активируется HDC-резерв:

```
query = unbind(context_codes, hdc_memory[prefix])
candidates = top-k cos(query, all_codes)
```

Этот сигнал интегрируется в RRF (Reciprocal Rank Fusion — метод обратного рангового слияния) вместе с графовыми, синтаксическими и векторными сигналами.

## 6. RRF-слияние: как принимается решение

При генерации следующего токена все источники знаний объединяются через взвешенное слияние обратных рангов:

| Источник | Вес | Что даёт |
|----------|-----|----------|
| Граф связей | 0.7 | Семантическая близость через граф |
| N-граммы (синтаксис) | 0.15/k | Статистическая вероятность |
| Векторная близость (сектор) | 0.15 | Геометрическая близость на сфере |
| HDC n-gram резерв | 0.10 | VSA-декодирование при нехватке данных |
| Априорная частота | 0.02 | Частотный приоритет |
| Гомеостатический буст | ×1.3 | Усиление недоиспользованных концептов |

Дополнительно:
- **Бонус центроида интента**: концепты, умеренно близкие к запросу (cos ~0.5), получают усиление
- **Блокировка n-грамм**: повторяющиеся n-граммы блокируются
- **MMI-штраф**: штраф за слишком вероятные токены (избегание тривиальности)

## 7. Дистилляция знаний Qwen

Внешняя модель (Qwen 3.4B) используется не как генератор, а как источник семантических связей.

### 7.1 Процесс

1. На корпусе из 30М символов предвычисляются косинусные близости между всеми парами токенов через эмбеддинги Qwen (слои 12–24).
2. Пары с count≥3 проходят фильтр: 20.6M → 1.53M высоконадёжных пар.
3. При STDP-тренировке каждая пара токенов получает LR-модулятор:

```
factor = get_factor(cos_sim):
    cos < 0.15 → 1.0 (нейтрально)
    0.15 ≤ cos < 0.20 → 1.0 — (cos-0.15)/0.05·0.15 (линейное отталкивание)
    cos ≥ 0.20 → 1.0 + cos·0.3 (кап 1.5)
```

### 7.2 Инвертированный кластерный потенциал

Редкие концепты с высокой ошибкой (CE) получают усиление кластерного потенциала до 1.2. Хорошо изученные — снижение до 0.8. Механизм противодействует эффекту «богатые становятся богаче».

## 8. Адаптивный учебный план

Процесс обучения подстраивается под состояние модели:

- **Оптимизатор параметров** отслеживает тренды косинуса, перплексию, обновления концептов; на лету настраивает скорость обучения, PMI-ключи, интенсивность выборки
- **Поконцептный трекер ошибок**: EMA ошибки предсказания на каждый концепт
- **Самостоятельный учебный план**: после каждого чекпойнта строки сортируются от трудных к лёгким
- **Флуктуация**: ланжевеновский дрейф с PPMI-взвешенным шумом для выхода из локальных аттракторов

## 9. Архитектура процесса обучения

```
Исходный текст (русский, SentencePiece BPE)
  ↓
Построение пар (контекстное окно 2–5):
    взвешивание по расстоянию · частоте · PMI · полю · Qwen
  ↓
GPU микробатч:
    STDP → L1 сжатие → Негативная выборка → Контрастив →
    Центроид → Латеральное торможение → HDC n-gram память
  ↓
Поконцептный EMA трекер ошибок → Оптимизатор параметров → Чекпойнт
```

### Периодические адаптации

| Каждые | Действие |
|--------|----------|
| 1 эпоху | Хеббово обновление полей W_proj |
| 2 эпохи | Адаптация L1-лямбд по концептам |
| 3 эпохи | Проверка ёмкости (рост/сжатие поля) |

## 12. Защита от коллапса и переполнения

### 12.1 Collapse Guard: авто-усиление латерального торможения

Средний косинус между случайными концептами (cos_mean) отслеживается на каждом чекпойнте. Если он превышает 0.08 — ранний признак коллапса пространства:

```
scale = 1.0 + (cos_mean - 0.08) × 50
inh_strength = clamp(default × scale, min, max)
```

При cos_mean = 0.09 сила торможения ×1.5, при 0.12 ×3.0. Если косинус падает ниже 0.04 — сила возвращается к базовой. Это предотвращает «тихий коллапс», когда все векторы медленно стягиваются к общему центру из-за STDP и центроидного притяжения.

### 12.2 HDC n-gram memory: LRU-кэш

Накопление HDC-представлений всех биграмм может привести к переполнению памяти (до 11 GB в худшем случае). Решение:

- `hdc_memory_max = 50000` — жёсткий лимит записей
- FIFO-очередь: при превышении лимита вытесняется самая давняя запись
- При доступе к записи через `hdc_predict` она перемещается в конец очереди
- Каждый STDP-батч добавляет не более длины предложения новых биграмм

Это гарантирует, что HDC-память занимает не более 50K × 2048 × 4B ≈ 400 MB, с автоматическим вытеснением редко используемых n-грамм.

### 12.3 Rescore с батчированием

Self-paced curriculum (`_rescore_lines`) теперь обрабатывает строки группами по 256, с прогресс-индикацией каждые 5000 строк. Это улучшает utilisation GPU и даёт прозрачность на больших корпусах.

## 13. Нейроморфное соответствие

FCF — единственная известная модель уровня «язык», принципиально совместимая с нейроморфными процессорами. Ниже — почему.

### 13.1 Нет обратного распространения

Все обновления — STDP, Hebbian, L1 soft-thresholding — вычисляются из локально доступной информации (пре- и пост-синаптическое состояние). Никакого глобального градиента. На кремнии: мемристорный кроссбар реализует STDP как изменение проводимости, пропорциональное `V_pre · V_post`.

### 13.2 Аддитивные обновления = синаптические события

`code[cid] += lr · Δ` — это единичное синаптическое событие на нейроморфном чипе. Время: ~1 pJ против ~1 nJ на GPU и ~1 µJ на CPU.

### 13.3 Разреженность и событийность

95% словаря простаивает в любой момент. L1 держит плотность кода ~8%. Нейроморфные чипы энергоэффективны именно на разреженных, событийных нагрузках.

### 13.4 Динамическая ёмкость = структурная пластичность

`grow_capacity()` / `prune_capacity()` — нейрогенез и прунинг синапсов. На нейроморфном чипе — выделение/освобождение физических рядов синапсов без перепрограммирования.

### 13.5 Секторный индекс = ассоциативная память

Иерархическое LSH (4+10+20 бит) — Content-Addressable Memory. Поиск по сектору — параллельное совпадение префикса. Российские разработки (Курчатовский институт «Алкуда», НИИСИ) проектируют CAM как аппаратный примитив.

### 13.6 HDC/VSA алгебра = система команд

bind(⊙), permute(ρ), bundle(+) — на чипе с VSA-микрокодом это один инструкционный цикл. HDC-резерв FCF (разовый unbind при нехватке данных) выполняется за O(1) независимо от размера словаря.

Подробнее — в отдельном документе `NEUROMORPHIC.md`.
